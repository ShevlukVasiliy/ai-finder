# Решения

| # | Решение | Почему |
|---|---|---|
| 1 | **Без бэкенда.** Весь анализ идёт в браузере (TypeScript). | Детекторы — эвристики, им не нужен сервер. Файлы не покидают устройство (приватность по ТЗ, раздел 12). Нет серверов, контейнеров и Redis. |
| 2 | **Без Docker и Terraform.** Инфраструктура — приватный бакет, API Gateway и два сервисных аккаунта, созданные через `yc` (`infra/setup.sh`). | Три ресурса не оправдывают IaC, state-бакет и отдельные ключи. К тому же в облаке исчерпана квота бакетов (25/25). |
| 3 | **API Gateway перед приватным бакетом.** | Одна точка входа, SPA fallback через `error_object`, бакет закрыт от прямого доступа. |
| 4 | **Авторизация CI — статический S3-ключ деплоера** с правами только на один бакет. | WIF не нужна: деплой — это только `s3 sync`, API облака не вызывается. |
| 5 | **P-01: символьная триграммная модель** (~100 КБ на язык) вместо KenLM на 1–2 ГБ. | В браузер нельзя отдавать гигабайты. Модель обучена на выдержках из Википедии (CC BY-SA) скриптом `scripts/train_ngram.ts`. Признак — вариация кросс-энтропии по предложениям. |
| 6 | **Итог = логистическая регрессия** с неотрицательными весами (`scripts/calibrate.ts` → `rules/weights.yaml`). Для изображений и кода без корпуса используются априорные веса из `rules/detectors.yaml`. | Неотрицательные веса делают каждый признак интерпретируемым («больше → больше похоже на ИИ»), и на этом построены советы. |
| 7 | **Корпус для калибровки — собственный мини-корпус** из 67 текстов (RU/EN, человек/ИИ) в `frontend/tests/quality/corpus`. | Taiga и прочие корпуса упираются в лицензии (открытый вопрос ТЗ). На этом корпусе in-sample ROC-AUC 1.0, при leave-one-out ≥ 0.8 (проверяется тестом). На реальных данных качество будет ниже: корпус маленький и писался вручную. |
| 8 | **Ожидаемый эффект совета считается контрфактически:** насколько упадёт score, если признак обнулить. Приоритет = эффект / трудоёмкость. | Так требует ТЗ (8.2). |
| 9 | **PDF — через pdf.js, DOCX/ODT — через zip+XML (fflate), RTF — собственный парсер.** | Всё работает в браузере, без серверных библиотек. |
| 10 | **Изображения:** C2PA ищется по JUMBF/caBX без полной валидации подписи, водяной знак — по квантованию DC-коэффициентов DWT-DCT (схема invisible-watermark). SynthID не проверяется. | Полная криптопроверка C2PA в браузере тяжела; наличие манифеста и заявленный `digitalSourceType` — достаточный сигнал. |
| 11 | **Код:** эвристики на регулярках вместо tree-sitter. | tree-sitter в WASM на каждый язык — мегабайты ради небольшой выгоды. |
| 12 | **Экспорт PDF — через печать браузера** (print stylesheet). | Корректная кириллица без встраивания шрифтов, ноль зависимостей. |
| 13 | **История версий — в `sessionStorage`** (без пикселей изображений). | Бэкенда и Redis нет, а ТЗ требует историю «в рамках сессии». |
| 14 | **Дизайн ориентирован на Hemingway Editor:** цвет обозначает только тип находки, оценка выводится текстом, подробная статистика свёрнута. | Первые варианты выглядели как типовой сгенерированный UI (индиго, карточки, полоски, кремовая палитра). По спискам признаков AI-дизайна (impeccable.style/slop, Fountain Institute) выбран функциональный референс. |
| 15 | **Storybook убран.** | Решение владельца продукта: компоненты покрыты Testing Library и e2e. |
| 16 | **Язык советов = язык интерфейса,** а пороги детекторов берутся по языку текста. | Иначе английский код давал английские советы при русском интерфейсе. |
| 17 | **Внешняя выборка из `Jinyan1/COLING_2025_MGT_multingual`** (RuATD/M4/MAGE): 160 RU + 160 EN, тексты 500–4000 символов; половина — обучение, половина — проверка. CoAT не взят: в нём отдельные предложения от моделей перевода и перефразирования, это не наш жанр. | Свой корпус слишком мал и написан вручную. Внешние данные дают честную оценку на отложенной выборке. |
| 18 | **Детектор S-07 «ответ ассистента»** (рамка-вступление, ярлыки-подзаголовки, итоговая строка, предложение помочь). | Современные ответы чат-ботов не содержат «эссейных» штампов, и старые признаки их пропускали. |
